# 部署独立临时中转服务

这些模板用于 Linux 服务端。源码位于仓库的 `relay/`，配置和数据库放在源码之外。这里没有真实服务器地址、令牌或证书。

部署前选择已经通过测试的提交，在部署记录中保存完整提交号。GitHub 的代码合并不会自动部署，也不会更新已安装的桌面程序。

## 路径约定

| 用途 | 路径 |
|---|---|
| 仓库检出 | `/opt/mouchen` |
| 中转源码与独立虚拟环境 | `/opt/mouchen/relay` 和该目录中的 `.venv` |
| 私有配置 | `/etc/ai-relay/config.json` |
| SQLite 和临时文件 | `/var/lib/ai-relay` |
| 服务账户 | `ai-relay`，无交互登录 shell |

在服务端检出经过验证的提交后，进入 `relay/`，运行 `python3 -m venv .venv` 和 `.venv/bin/python -m pip install -r requirements.lock`。不要与原业务后端共用虚拟环境。

## 配置

1. 创建独立服务账户，创建上述配置和数据目录。
2. 将 `relay/config/server-config.example.json` 复制到 `/etc/ai-relay/config.json`，把 `data_dir` 改成 `/var/lib/ai-relay`。
3. 给每台电脑或手机分配唯一设备名称和随机高强度令牌。`devices` 字典保存每个令牌的 SHA-256 十六进制摘要，原令牌通过私有渠道交给对应设备。
4. 配置文件由 root 拥有、服务账户可读，例如 `root:ai-relay`、权限 `0640`；数据目录归服务账户所有，权限 `0700`。
5. 每台电脑使用 `relay/configure.py` 写入该电脑自己的私有配置。不要把配置和令牌放到源码目录或 GitHub。

示例中的 `REPLACE_WITH_...` 不是可用密钥，必须替换。本服务不会替你创建或验证 GitHub 账号。

## 进程与 HTTPS

将本目录的 `ai-relay.service` 安装到 `/etc/systemd/system/`，核对路径后执行 `systemctl daemon-reload` 和 `systemctl enable --now ai-relay`。

服务只监听 `127.0.0.1:8788`。**只能运行一个 worker**，不能让多个实例共享同一个数据目录。Nginx 模板使用 `relay.example.com`；替换为自己的地址，并先通过合适的方式配置有效证书及自动续期，再启用 HTTPS 入口。

不要把没有 HTTPS 的数据接口直接暴露到公网。当前实现只加密传输，服务器临时文件并非端到端加密。

可用 `curl http://127.0.0.1:8788/health` 检查本机服务，然后从另一台设备验证 HTTPS、上传、下载、校验和确认清理。配置和证书维护属于部署环境，不随源码更新覆盖。

## 更新和回退

记录当前源码提交和依赖版本。确认没有需要保留的进行中上传后，停止服务，切换到已验证的新提交，安装该提交的依赖并重新启动，核验连接与清理状态。

如果新版本出现问题，同样停止服务，恢复之前的源码与依赖并重启。只有数据库格式兼容时才能直接回退代码；涉及数据库迁移的版本应预先规划备份与恢复，不能通过删除数据库解决版本问题。

这里只保留临时副本，不替代发送端原件和接收端归档的备份。默认 24 小时过期、所有目标确认后删除，元数据最多保留 7 天和 1 万条已完成记录。
