# 公开核心架构 / Public Core Architecture

## 当前可运行范围

本仓库刻意只公开与外部系统解耦的判断核心：

~~~text
synthetic event
  → derivation and attribution
  → goal-gap or problem detection
  → evidence-backed advice candidate
  → proactive value score
  → earned speaking ceiling
  → consent, pause, duplicate and context gates
  → structured decision
~~~

领域模型位于 backend/app/domain，跨系统数据约定位于 shared。examples/demo.py 构造虚拟目标和事件，可在无账号、无密钥、无数据库、无网络的环境中运行。

## 设计决定

### 证据先于结论

观察到的文本不自动等于用户的事实、立场或承诺。每条事件保留来源、时间、置信度和敏感级别；建言保留当时使用的证据快照与可验证预测。

### 重要程度不等于行动权限

L1—L4 表示建言强度，A0—A4 表示行动权限。高等级建言不能自动取得更高行动权限。外部或不可逆动作必须在执行前得到针对当次动作的明确确认。

### 发言权需要通过结果积累

新领域默认限制发言强度。只有当历史判断数量、准确度、校准度、效用和时机达到门槛时，系统才能提高发言上限；灾难性错误会立即降低上限。

### 情境闸门优先

撤回同意或全局暂停会直接阻止输出；重复问题合并到已有线程；会议、驾驶、睡眠和免打扰时段通常进入简报队列。紧急性可以改变提醒时间，但不能绕过已获得的发言权限。

## 未来完整闭环

~~~text
用户授权的信号 → 本地过滤与最小化 → 可追溯记忆
→ 分析与建言草稿 → 风险闸门 → 必要时用户确认
→ 有限、可撤销的动作 → 外部状态回读 → 结果学习
~~~

采集、跨设备同步、模型路由、认证、生产部署和动作执行不在首版公开仓库中。它们只有在权限、隐私、安全测试和真实状态回读成熟后，才适合进入公开接口或经过审查的连接器生态。
